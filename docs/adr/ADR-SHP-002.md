# ADR-SHP-002 — Explicit host-aggregate projection

- **Status:** Approved
- **Owner:** B3A
- **Decision:** SQLite is complete host state; PostgreSQL receives the explicit minimum launchable definition: typed placement, Team/Variant, typed project git ref, ordered nonempty prompt refs, launcher/ATM provenance, variant-qualified members, per-variant backend/runtime bindings, assignments/state, enrollment, and source-qualified cursor/tombstone metadata. Resolved paths, prompt bodies, credentials, terminal handles, and observations stay local. The schema-owned open `DefinitionStore` is the sole durable definition read/atomic-commit seam: only `shpherd-store-sqlite` implements it in production, while `shpherd-service` B5/B6 consume its commit/read capabilities through static composition; every other implementation or consumer edge is forbidden by boundary manifests. B9B receives complete local launch data only through B6's sealed read-only `LaunchPreparationReader`, never through `DefinitionStore` or PostgreSQL.
- **Alternatives rejected:** generic replication, shared SQL, last-write-wins, or copying paths/logs/credentials.
- **Consequences:** projection additions require an allowlist migration and exclusion tests. Definition persistence cannot be recreated inside a service, daemon, poller, or second engine path.
- **Evidence:** B3A allowlist/exclusion, DefinitionStore compile-fail edges including direct B9B rejection, and empty-target hydration fixtures; B4 atomic definition-store tests; B6 complete launch-preparation-reader tests; and B9A two-host projection replay/conflict tests.
